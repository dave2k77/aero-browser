# Requirements and correction traceability

## Authority and reading rules

The [specification](specification.md#13-requirement-register-and-acceptance-ownership) owns product requirements; the [implementation plan](implementation-plan.md#8-step-by-step-implementation-backlog) owns package definitions, exact future test contracts, dependencies and execution status. This A01 matrix maps obligations, not implementation evidence. Every row is `not_started`: no application behavior or future test execution is certified here. Use the [handoff](handoff.md) for the current checkpoint, not historical environment statements in the plan.

There are exactly 26 product requirement rows and 31 source-correction rows below. `REQ-*` and `SPEC-*` are distinct registers. Source links identify canonical sections; PDF page numbers in correction rows preserve the reviewed historical provenance without reinterpreting its examples as working code. Package IDs are those of the canonical plan, not crate names.

**Proof notation:** `path :: name` is an exact planned test file and named test; `suite` explicitly means the plan names a test file/command but supplies no individual test name. These are planned paths, intentionally code spans rather than links to nonexistent files. A **manual**, **provisioning**, **build**, or **documentation gate** is not an automated test. No new test names are invented to fill gaps in the plan. A row can require multiple proofs; a representative named test alone does not discharge its entire acceptance obligation. The named package's full assertions remain mandatory.

**Milestones:** G0 foundations; GV accepted actual-viewport evidence; G1 supplier CLI slice; G2 recovery; G3 guarded breadth; G4 task desktop; G5 release. “Optional” means not shipped until selected, provisioned, tested and justified; it never waives a mandatory baseline in the same row. Follow the [integrated dependency schedule](implementation-plan.md#integrated-dependency-schedule--do-not-execute-alphabetically), including early F01/F08/F10, N09 pause-on-close and G11 history.

## Interpretation and remaining proof gaps

- Exact test names are copied from the plan; a suite/filter is explicitly labelled where the plan does not name an individual test. N03, N08, N15, N20, N21 and N23 need implementer-assigned individual names when their existing suite assertions are turned into tests. Do not report a filter or zero matched tests as a pass.
- SPEC-23 and SPEC-26 currently have contract/claim review gates but no dedicated behavioral regression name in the plan. Their related tests are not substitutes for the missing dedicated proof. This matrix preserves that limitation instead of inventing coverage.
- Provisioning, native presentation/a11y, isolated keyring, package installation/signing, actual-model evaluation and owner-curated holdout evidence remain their own gates. Scripted browser integration is not model-quality evidence; documentation coverage is not feature completion.
- Review [architecture](architecture.md) and the ADRs for ownership and safety invariants. Update the canonical specification/plan first when scope or test contracts change, then this index. Execution evidence and package lifecycle remain in the plan/handoff; the `not_started` rows here do not authorize execution, commits or publication.
